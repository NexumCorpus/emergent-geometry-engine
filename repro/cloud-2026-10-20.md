## Tamper tests (each in a temp copy of the clone, never in the repo)

1. Changed the Peschel anchor in `verify/__main__.py` by 1e-8 (above the 1e-9 tolerance). `python -m verify` printed `[FAIL] peschel:anchor_N8_L4` and `OVERALL: FAIL (10/11 checks)`, exit 1. Rejected, as it should be. (A first attempt shifted it by 1e-11, which is below tolerance, and correctly still passed.)
2. Added 1e-6 to the exact-diagonalization entropy in `verify/ed.py`. `python -m verify` gave `[FAIL] peschel:vs_independent_ED`, exit 1. `phase0_gate.py` gave `PHASE 0 GATE: FAIL (12 passed, 1 failed)`, exit 1. pytest gave `5 failed, 103 passed`. Rejected by all three.
3. Moved the "critical" point in `check.py` from p=0.12 to p=0.30 (a null: no transition there). `check.py 777` failed three of six assertions, exit 1. Rejected. One side note: in this null run the "forman dip vs high" line still said `ok`, comparing two independent 50-trajectory ensembles at the same p=0.30 (1.507 vs 1.736, gap 0.23 against the 0.2 margin). So the Forman tail-to-tail sampling spread at 50 trajectories can reach roughly the size of the 0.2 margin. The check still failed as a whole because the other assertions caught it, and the real-claim gaps (0.39 or more) stay well clear of that spread. This is not a defect, but it shows the Forman margin is less conservative than the "~4x smaller than the gaps" wording suggests.

## README gaps a stranger would hit

1. **Python 3.11 is claimed but does not work.** README says "Python 3.11+". `numpy==2.5.0` requires 3.12 or newer, so installation fails on 3.11. Either say "Python 3.12+" or relax the pins. This is the one blocking defect.
2. **The "gate 13/13" claim has no command in the README.** The Evidence table claims "acceptance gate 13/13" and links docs/PHASE0_REPORT.md, but the README never mentions `python phase0_gate.py`. Run after the README's own install steps, it reports 12 passed, 1 skipped. 13/13 needs the optional `requirements-quantum.txt` step as well. The gate does label the skip honestly.
3. **The architecture diagram puts the robustness harness inside the verifier.** It lists "graph-construction robustness harness" under "VERIFIER (separate code path, no kernel imports)". In the code the harness is `geometry/robustness.py` (kernel), and it runs only from `phase0_gate.py`, not from `python -m verify`. The "11 checks" count in the quickstart is correct; the diagram is not.
4. **docs/PHASE0_REPORT.md is stale.** It says "71 tests green" (now 104 pass + 4 skip, or 108 with QuTiP) and says the spectral bound is tight on "K₅/Q₅", while the code checks Q₃. The listed residuals (e.g. 6.66e-16) differ from today's output (0.00e+00), which is expected float variation but isn't flagged as historical.
5. **KNOWN-STATE.md contradicts requirements.txt.** It reports "84 passed" with GraphRicciCurvature 0.5.3.2; requirements.txt pins 0.4.5 and the suite now has 108 tests.
6. **claim.json is not stranger-runnable as written.** Its `check` field is `E:\_phase0_test_venv\Scripts\python.exe` and its statement names "repo E:/emergent-geometry-engine, master b88b122". The README command works because `check.py` no longer reads claim.json, but the file still points at a local Windows machine. (Commit b88b122 does exist in the public history.)
7. **.gitignore ignores `artifacts/` and `*.png`**, yet `artifacts/` and its PNGs are committed evidence. That's harmless for the repro, but new artifacts a contributor generates will silently not be tracked.
8. Minor: the timings in the README are conservative on this VM (verify 0.3 s vs "~3 s", pytest 5 s vs "~15 s"). That is not a problem, just noted.

Not re-run: the full Phase-3 sweep (L = 32/48/64, 200 trajectories per point) and the Phase-4 grokking result. The README offers only the 50-trajectory `check.py` as the stranger-facing re-derivation, and that passed.
